# Dependency helper: second review

## Implemented

- Runtime TOML, extras, standard dependency groups (including include-group), and PDM development groups are separate selections. Group edits use the same undo-aware writer.
- Requirements files remain selectable; TOML-only mode excludes unrelated example constraints.
- Runtime import view marks conventional tests/docs/examples/conversion folders and inactive declared extras as non-runtime. All-project view is available.
- ImportError fallback imports and feature-gated imports are conditional; main-entry imports remain required.
- Bare Git source requirements retain their URL, revision and subdirectory through uv installation. Their package identity remains unknown until metadata identifies it; no repository-name guessing.
- Missing/invalid environments show setup guidance and no install buttons.

## Verification

50 focused tests passed, including real pending-file undo tests and a subprocess boundary test proving Git URLs survive into the uv command. All seven repositories scanned; every discovered TOML group also scanned without parser errors. The Ultralytics selectors were verified in the actual UI. ## Remaining findings from the expanded sample

### nanoGPT

wandb is now conditional; model stays local. No manifest exists; README installation commands are not treated as declarations.

### ignite

Runtime TOML excludes development requirements in TOML-only mode. The Git requirement in requirements-dev.txt is recognized as a source and retains its revision, but its bare URL does not establish an import identity.

### examples

The selected minGPT requirements enforce torch>=2.7. urllib2 fallback is conditional. Independent examples remain selectable through 32 requirements files.

### timm

Runtime and PDM:test are separate selections. yaml aligns with pyyaml. Imports in conversion scripts are non-runtime; lazy optional readers still cannot always be inferred from syntax alone.

### whisper

Runtime dependencies and the dev extra are separate. more_itertools aligns through canonical package-name normalization. Platform-marked triton is preserved, but the table does not yet filter declarations against the selected interpreter platform.

### torchmetrics

28 requirements files found; base.txt provides runtime constraints. Package extras generated by setup.py are not inferred or executed; their source requirements files can be selected directly. RequirementCache-driven lazy imports remain a static-analysis limitation.

### ultralytics

Runtime TOML can be selected independently of four example requirements files. All 16 extras are selectable. Packages declared only in inactive extras are shown as non-runtime. Dynamically checked/export-only packages without declarative ownership can still appear required.
